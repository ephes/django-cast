0.2.66 (unreleased)
-------------------

- Honor Wagtail editorial locks on Post and Episode editor API PATCH requests,
  returning ``409 page_locked`` when a lock applies to the caller. Existing
  revision-conflict and draft-only errors retain precedence. Successful edits
  now record a ``wagtail.edit`` audit entry atomically with the new revision.
- Move body section selection and merging into the transport-neutral
  ``cast.content`` package, shared by the editor API and test-only Wagtail v3
  adapter. Existing editor payloads and section-preservation behavior are unchanged.
  The internal ``PostEditorMixin.body_section_order`` attribute is removed;
  overriding it no longer changes section insertion order.
- Add an isolated Wagtail 8 v3 compatibility experiment to the Wagtail 8 tox
  environments. It proves bearer-authenticated schema discovery and public
  Post/Episode page exposure without mounting v3 in normal django-cast URLs or
  enabling any Cast fields for v3 writes in production.
- Extend the disposable experiment with selected scalar draft fields. It
  reproduces write-response failures from Cast's computed v2 fields and shows
  that partial updates are based on the live row rather than the latest draft.
- Add a disposable revision-aware update adapter that returns a truthful
  transport-native response, preserves omitted values from the latest Post or
  Episode draft, and rejects stale base revisions without creating a revision.
  Publishing remains deliberately unavailable through the adapter.
- Extend the Wagtail 8 experiment across Episode publication paths. Cast's
  shared publication policy rejects audio-less create, edit, and standalone
  publication while permitting a valid audio Episode. The scheduler also
  rechecks a revision approved through v3 if its audio later disappears.
  Scheduling input is measured separately below.
- Confirm that native v3 actions enforce Wagtail's tree-scoped change and
  publish permissions for separate drafting and publishing users. Native API
  tokens do not require Wagtail admin access and cannot carry Cast's separate
  ``write`` and ``publish`` scopes.
- Measure draft-state update behavior in the disposable v3 adapter. Wagtail's
  scheduled-publication lock already rejects scheduled Post and Episode edits,
  while preserving Cast's draft-only live-page safeguard requires an explicit
  adapter precondition.
- Measure revision-bound publication in the Wagtail 8 experiment. Stock v3
  standalone publication makes the latest Post or Episode revision live even
  after a caller selected an older one. The disposable adapter requires the
  selected revision in ``If-Match``, returns ``409`` without publishing either
  revision when it is stale, and otherwise delegates to Wagtail's publish
  action and Cast's Episode publication policy.
- Measure scheduling input in the Wagtail 8 experiment. Stock v3 page schemas
  do not accept ``go_live_at`` or ``expire_at``. After a disposable opt-in,
  revision-bound publication schedules the selected revision and Cast's
  Episode audio policy still applies, but a partial update can set a go-live
  time after an existing expiry time.
- Measure draft reads and previews in the Wagtail 8 experiment. Stock v3
  detail reads fail for Cast Posts and Episodes because inherited HTML fields
  receive no request context, and draft reads are gated by explore rather
  than edit permission. A disposable adapter route renders the latest draft
  through Wagtail's preview machinery under the editor API's edit rule. The
  experiment also records that preview rendering sees the session user, not
  the bearer token, and that Cast's preview synchronizes stored media
  relationships.
- Measure body conversion in the Wagtail 8 experiment. Native v3 StreamField
  writes replace the whole body and accept images the caller cannot choose.
  A disposable adapter converts Cast author blocks through ``cast.content``,
  preserves the other body section, and reports Cast's field-level errors.
- Measure media handling in the Wagtail 8 experiment. Stock v3 image uploads
  apply Wagtail's validation and collection scoping, but can store an image in
  a different collection than requested and do not require ``choose``
  permission. v3 exposes no Cast audio, video, or transcript routes.
- Add PostgreSQL-only threaded tests to the Wagtail 8 experiment. On a local
  PostgreSQL 17 server they show that the disposable adapter's page and
  revision locks make concurrent draft saves, schedule approvals, and
  same-base updates wait; they are skipped on SQLite.
- Complete the Wagtail v3 evaluation with an architecture decision: keep the
  existing editor API as the supported authoring transport, reuse Wagtail's
  actions, locks, and forms beneath it, and defer direct v3 adoption. No
  production v3 routes, client migrations, or route retirements are part of
  this release.
