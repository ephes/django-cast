0.2.68 (unreleased)
-------------------

- ``media_replace --yes`` now exits with ``CommandError`` (non-zero status)
  when at least one replacement failed. It used to print ``errors=<n>`` in the
  summary and still exit successfully, so scripts could not tell a failed or
  partial run from a clean one. The remaining paths are still attempted and the
  summary is still printed first. Automation that relied on the old exit status
  needs to handle the failure.
- Add ``media_backup --refresh-changed``. ``media_backup`` skips every path
  that already exists in the backup, so a file changed in place (for example by
  ``media_replace``) kept its old bytes in the backup forever and
  ``media_restore`` would have brought the old file back. The new option
  compares existing files by content (size as a shortcut for "different",
  SHA-256 of both copies when the sizes match) and overwrites backup copies
  that differ. The new bytes are staged in the backup storage first and the
  previous copy is never deleted, so a production file that cannot be read, a
  staged copy that cannot be written, or a backup storage that does not
  overwrite existing names leaves the previous backup copy in place. If the
  final overwrite itself fails, what remains under the path depends on the
  backup storage backend: object storage keeps the previous object, a
  backend that writes in place (``FileSystemStorage`` with
  ``allow_overwrite``) can leave a partial file. Failures are reported, the
  remaining paths are still processed, and the command exits non-zero. The
  default mode and ``media_restore`` are unchanged.
- Send known-speaker voice references whenever a diarized transcript request
  names only the audio, such as ``generate_transcripts --audio-id``. The
  episode is now resolved from the audio when it belongs to exactly one
  episode; before, such requests silently ran without references and returned
  anonymous diarization labels only.
- Warn when known-speaker recognition is enabled but a diarized request sends
  no voice references. ``generate_transcripts`` prints the warning, and the
  service logs it on ``cast.voxhelm.service`` for queued requests.
- ``recalc_video_posters`` now exits with ``CommandError`` (non-zero status)
  when at least one poster could not be recalculated. It used to print
  ``errors=<n>`` and still exit successfully. All videos are still attempted,
  healthy ones are saved, and the summary is printed first. Automation that
  relied on the old exit status needs to handle the failure.
- ``styleguide_prefetch --with-renditions`` no longer leaves
  ``CAST_STYLEGUIDE_GENERATE_RENDITIONS`` switched on. The command changed the
  process-wide setting and never put it back, so after ``call_command`` in a
  long-running process the styleguide kept generating renditions, also when
  the command had failed. The previous value (or the absence of the setting)
  is now restored on success and on failure.
