0.2.68 (unreleased)
-------------------

- Apply the transcript glossary to transcripts. After every Voxhelm import,
  contributor and show-term variants are replaced automatically in the
  Podlove, DOTe and WebVTT text, and fuzzy matches of contributor names, show
  terms and show-note spellings are stored as proposals. The raw text, the
  replacements, proposals and editor decisions live in the new private
  ``Transcript.corrections`` sidecar (migration ``0086``), which is never
  served publicly. Corrections change only segment text, so known-speaker
  application and approved speaker mappings are unaffected. Audio used by
  several episodes gets no corrections until an editor picks the episode. The
  new ``apply_transcript_glossary`` command re-applies the glossary after
  edits. A *Glossary corrections* section on the transcript edit view shows
  the replacements and the proposals grouped by correct spelling with their
  context, and lets editors approve or reject a group or single occurrences,
  add an original to the glossary, reject replacements, re-apply the glossary
  and pick the episode for shared audio; see :ref:`transcript_glossary_review`.
- Add the data for a transcript glossary that will correct misheard names and
  terms in transcripts. Contributors get a private ``transcript_variants``
  field (one ``variant => replacement`` per line, scoped to episodes that
  credit the contributor). The new ``TranscriptGlossaryTerm`` snippet holds a
  podcast's correct spellings and their misspellings: a term is unique per
  podcast ignoring case, a variant belongs to one term, and single-word
  variants that are common words in the podcast's transcript language are
  refused, using built-in English and German lists derived from Tatoeba
  (CC BY 2.0 FR). ``import_transcript_glossary <podcast> <file.json>`` (with
  ``--dry-run``) loads a list for one podcast; see :ref:`transcript_glossary`.
  Migration ``0085`` adds the field and the table.
- Keep approved transcript speaker mappings current when the public files
  are rewritten from the received ones. Mappings used to be compared with a
  hash of the current Podlove, DOTe and WebVTT bytes, so applying
  known-speaker suggestions turned every approval stale and hid the names.
  The new ``Transcript.source_fingerprint`` holds the hash of the artifacts as
  received from Voxhelm or uploaded in the admin; speaker application and
  ``rewrite_speaker_labels`` leave it unchanged, a new import or upload still
  marks approvals stale. A migration sets it for existing transcripts from
  their current files (it reads every stored transcript once).
- Fix editing a transcript in the admin when only some of its files are
  uploaded, for example a new Podlove file while the DOTe and WebVTT files are
  kept. Saving failed with ``ValueError: seek of closed file`` because the form
  read the kept files again after the edit view had closed them. Only new
  uploads are validated now.
- Write internal page links in feed item descriptions as absolute URLs.
  Rich-text links to other pages used to be root-relative in RSS/Atom output
  and broke in feed readers. Post, blog index and other HTML pages keep
  relative links. API HTML fields rendered with ``render_for_feed`` (the
  default) also get absolute links; pass ``render_for_feed=false`` for
  relative ones.
- Fall back to the plain theme selector fragment for HTMX requests when a
  theme omits the optional ``select_theme.html`` template.
- Report missing soft-required theme templates as ``cast.W002`` system check
  warnings, including configured themes and templates provided by custom loaders.
  Template syntax errors also produce warnings rather than aborting startup checks.
- Rename generic ``Speaker N:`` cue prefixes as well as voice tags through
  ``Transcript.rewrite_speaker_labels``. Renamed prefixes become voice tags
  for subsequent renames and public speaker sanitization.
- Resolve Voxhelm API base and token as a pair from one configuration level.
  Incomplete pairs no longer inherit deployment credentials. Move mixed-level
  credentials to one level before upgrading; changing the Wagtail API base
  requires re-entering its token. Saving with both credential fields blank
  removes the site pair so deployment credentials can be used.
- Exclude view-restricted pages from navigation links in blog, post and
  feed contexts, including for signed-in visitors. Pages beneath a restricted
  page are also omitted; member-only sites must supply their own navigation.
  Which pages are candidates for the navigation is unchanged.
- Render shared feed descriptions with the blog/site default theme, ignoring
  visitor session, query and internal preview theme overrides.
- Rate-limit comment posting. Both comment post views used to accept any
  number of comments from one client. They now allow
  ``CAST_COMMENTS_POST_RATE_LIMIT`` posts (default ``20``) per
  ``CAST_COMMENTS_POST_RATE_WINDOW`` seconds (default ``600``) per logged-in
  user or anonymous client address and answer further posts with ``429`` and
  ``Retry-After``; the AJAX view returns the usual JSON error shape so the
  bundled script shows the message at the comment field. Previews are not
  counted, and ``0`` disables the limit. Sites behind a reverse proxy need
  ``REST_FRAMEWORK["NUM_PROXIES"]`` for the client address to be correct; see
  :ref:`CAST_COMMENTS_POST_RATE_LIMIT <cast_comments_post_rate_limit>`.
- ``media_replace --yes`` now exits with ``CommandError`` (non-zero status)
  when at least one replacement failed. It used to print ``errors=<n>`` in the
  summary and still exit successfully, so scripts could not tell a failed or
  partial run from a clean one. The remaining paths are still attempted and the
  summary is still printed first. Automation that relied on the old exit status
  needs to handle the failure.
- Add ``media_backup --refresh-changed``. ``media_backup`` skips every path
  that already exists in the backup, so a file changed in place (for example by
  ``media_replace``) kept its old bytes in the backup forever and
  ``media_restore`` would have brought the old file back. The new option
  compares existing files by content (size as a shortcut for "different",
  SHA-256 of both copies when the sizes match) and overwrites backup copies
  that differ. The new bytes are staged in the backup storage first and the
  previous copy is never deleted, so a production file that cannot be read, a
  staged copy that cannot be written, or a backup storage that does not
  overwrite existing names leaves the previous backup copy in place. If the
  final overwrite itself fails, what remains under the path depends on the
  backup storage backend: object storage keeps the previous object, a
  backend that writes in place (``FileSystemStorage`` with
  ``allow_overwrite``) can leave a partial file. Failures are reported, the
  remaining paths are still processed, and the command exits non-zero. The
  default mode and ``media_restore`` are unchanged.
- Send known-speaker voice references whenever a diarized transcript request
  names only the audio, such as ``generate_transcripts --audio-id``. The
  episode is now resolved from the audio when it belongs to exactly one
  episode; before, such requests silently ran without references and returned
  anonymous diarization labels only.
- Warn when known-speaker recognition is enabled but a diarized request sends
  no voice references. ``generate_transcripts`` prints the warning, and the
  service logs it on ``cast.voxhelm.service`` for queued requests.
- Name a guest without a voice reference when applying known-speaker
  suggestions. Before, such a guest's lines stayed blank, and on episodes whose
  anonymous ``Speaker N`` labels had approved contributor mappings a
  known-speaker re-run lost the guest's name. When exactly one assigned
  contributor got no reference and exactly one diarization label is tied to no
  known speaker, the uncertain segments on that label now get the
  contributor's name. Ambiguous cases still stay blank. The label map comes
  from Voxhelm's ``raw_diarization_labels`` summary or, for older sidecars,
  from the same confident-segment vote.
- Stop sending the speaker-count hint (``num_speakers``) with known-speaker
  Voxhelm jobs. With a fixed count, pyannote merged a guest and a host whose
  voices were similar into one label and spent the freed label on noise, so
  many lines of such episodes stayed blank or got the wrong name. Jobs with
  voice references now let pyannote find the number of speakers itself.
  Diarized jobs without voice references still send the episode's
  contributor count. The task reference keeps its ``-<n>-speakers`` suffix.
- Keep waiting for a Voxhelm job when a status poll loses the connection.
  ``generate_transcripts`` and the admin completion task used to abort on the
  first refused or dropped connection, and some of them
  (``RemoteDisconnected``, ``IncompleteRead``, socket resets and timeouts)
  escaped as uncaught exceptions instead of ``VoxhelmError``. All
  connection-level failures of Voxhelm requests now raise
  ``VoxhelmConnectionError`` (a ``VoxhelmError``); polls retry them with a
  warning until ``CAST_VOXHELM_POLL_TIMEOUT``. Submissions are not retried.
  When completion fails after a job was submitted, the error message names
  the job, so its result can be imported with
  ``VoxhelmTranscriptService.complete_audio_job`` instead of transcribing the
  audio again.
- ``recalc_video_posters`` now exits with ``CommandError`` (non-zero status)
  when at least one poster could not be recalculated. It used to print
  ``errors=<n>`` and still exit successfully. All videos are still attempted,
  healthy ones are saved, and the summary is printed first. Failed poster
  generation is now counted at all: ``Video.create_poster()`` logs and
  swallows errors so uploads succeed without a poster, which made the command
  report ``errors=0`` for them. The command asks for the error
  (``create_poster(raise_errors=True)``, default unchanged) and also counts a
  video that ends up without a wanted poster. Automation that relied on the
  old exit status needs to handle the failure.
- ``styleguide_prefetch --with-renditions`` no longer leaves
  ``CAST_STYLEGUIDE_GENERATE_RENDITIONS`` switched on. The command changed the
  process-wide setting and never put it back, so after ``call_command`` in a
  long-running process the styleguide kept generating renditions, also when
  the command had failed. The previous value (or the absence of the setting)
  is now restored on success and on failure.
- ``scripts/benchmark_typeahead.py`` (development benchmark, not shipped)
  checks its target before it migrates or writes. ``seed`` and ``all`` ran the
  migrations, pointed the default Site at the page tree root and created the
  benchmark user before refusing a database with real Blogs. A read-only
  preflight now refuses first: any settings module other than
  ``scripts.typeahead_benchmark_settings``, Blogs outside the
  ``typeahead-benchmark-`` prefix, pages outside those Blogs (other than the
  tree root and Wagtail's untouched default home page), and user accounts
  other than ``typeahead-benchmark``. Empty, freshly migrated and previously
  seeded benchmark databases work as before. ``scripts/benchmark_feeds.py``
  seeds through the same check.
- Clear the cache before every test. A feed response cached by one test was
  served to a later test that requested the same feed URL, so
  ``test_get_only_published_entries`` failed depending on the random test
  order.

- Protect ``media_stale`` cleanup with a configurable minimum storage-file age
  (``CAST_MEDIA_STALE_MIN_AGE_DAYS``, default 7 days). Skip unknown ages,
  re-check age and exact database file references before each deletion, and
  report files skipped as too young or newly referenced. Listing remains the
  default; the command does not delete database rows.
