0.2.65 (unreleased)
-------------------

- Make the legacy ``/api/audios/`` and ``/api/videos/`` collection endpoints
  read-only. Their unsupported create paths failed after writing uploaded files,
  leaving storage objects without database records. They now return ``405`` for
  ``POST`` without storing the upload. New clients should use the permission-aware
  editor media upload endpoints; the separate legacy ``/api/upload_video/``
  endpoint remains available during migration.
- Create a fresh RSS or Atom feed renderer for every cache miss, preventing
  concurrent requests from mixing blog, request, repository, or podcast-format
  state while preserving generated-response caching.

- Prevent RSS, Atom, podcast, and feed detail endpoints from exposing metadata
  for blogs or podcasts protected by direct or inherited Wagtail login,
  password, or group restrictions. These shared-cache endpoints now serve only
  unrestricted public feed roots.

- Fix stored cross-site scripting through editor API rich-text writes. Paragraphs
  and nested custom rich-text blocks now pass through Wagtail's feature-based
  HTML conversion before validation. Raw-HTML custom inputs are rejected;
  malformed rich text returns a structured 400. Returned HTML is normalized:
  formatting outside the configured rich-text features becomes ordinary text
  (enable features such as ``blockquote`` and ``code`` to retain them).
  Supplied Draftail comment-anchor keys are retained without adding random keys.
  Inline image/oEmbed markup returns an ``inline_embed`` validation error
  instead of being silently removed; even
  existing admin-authored inline media must be moved to structured media blocks
  before resubmitting its section. Existing pages and historical
  revisions are not rewritten: operators should review stored content and
  restorable revisions before lifting temporary API restrictions. See the
  editor API section in :doc:`../reference/api` for the exact scope.
- Reduce the public custom-player transcript cache freshness window from one
  hour to 30 seconds and require revalidation afterward, so transcript and
  contributor/speaker-mapping edits do not remain stale while immediate repeat
  opens avoid rebuilding the full sanitized payload.
- Make the known-speaker quick-apply action publish confident suggestions only.
  Uncertain hand-offs remain unchanged until an editor reviews them instead of
  being filled from a surrounding confident speaker automatically.
