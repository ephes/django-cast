0.2.67 (unreleased)
-------------------

- Add cross-document view transitions to the built-in ``bootstrap4`` and
  ``plain`` themes. Ordinary same-origin page loads crossfade under the
  ``cast-page`` transition type when the reader has no reduced-motion
  preference. HTMX pagination keeps its existing fade, and unsupported browsers
  load pages as before.
- Morph a post's title and first overview image (not counting audio player
  cover art) between blog lists and the post detail page in the ``bootstrap4``
  and ``plain`` themes. The new
  render-time script ``cast/js/post-view-transition.js`` names only the post
  being opened or left, during ``cast-page`` transitions. Sites that ship their
  own copy of a theme's ``base.html`` instead of extending it need to add the
  script to the ``<head>`` to get the morph.
- Render ``#paging-area`` during ``cast-page`` transitions in the
  ``bootstrap4`` and ``plain`` themes, so posts also morph back into the list on
  sites that give it ``content-visibility: auto``.
- Prevent the Podlove audio detail API from caching draft or restricted
  responses in Django's full-site cache. Such responses now use
  ``Cache-Control: private, no-store`` and vary on ``Cookie`` and
  ``Authorization``, so revoked credentials or group membership are checked on
  the next request instead of receiving a cached authorized response. Purge
  existing Podlove detail responses from application and downstream caches when
  deploying; the new headers cannot evict previously cached responses.
- Apply the private-response cache policy to raw Podlove JSON, PodcastIndex
  JSON, WebVTT, and chapters endpoints. Responses granted through restricted or
  draft pages use ``private, no-store`` and vary on ``Cookie`` and
  ``Authorization``. Purge existing endpoint cache entries on deployment.
  Previously public responses retain their cache lifetime after new restrictions;
  purge those URLs when immediate removal is required. HTML transcript views
  retain their existing behavior.
- Exclude Django 6.1.0 for CVE-2026-15830 reported by the dependency audit;
  require 6.1.1 or later on that branch while retaining patched Django 5.2
  and 6.0 support. Align the strict advisory-floor audit and compatibility
  environments with that minimum. Refresh application locks that retain 6.1.0.
- Raise the urllib3 security floor to 2.8.0 for the streaming and HTTPS-proxy
  advisories also exposed by checking every audit minimum. Keep both strict
  dependency audit jobs; refresh application locks retaining earlier urllib3.
